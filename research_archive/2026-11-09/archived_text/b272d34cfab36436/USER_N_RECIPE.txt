**关于 N，我建议现在固定成一套统一规则：保留合格目标的自然面数，在当前模型合同内允许到 799；每个条件任务最多增加一个合格的低面数版本；全程混合训练，先均衡父曝光；推理时显式指定 N。**

其中，**当前最值得先改的是解除统一 `N≤256` 的数据限制，让已经合格的复杂 Bench 目标能够进入训练。** 低面数增强是可选项，不必等所有目标都有两个版本，才继续数据扩充。

下面把定义、数据构建、采样、训练、推理和评价完整收口。这套建议依据已经完成的云端实验；它支持数据保真与覆盖方面的选择，尚未证明某个固定 N 或混合比例的条件生成质量最优。BENCH_FACE_RECIPE_REPORT.html[完整实验报告](sandbox:/workspace/scratch/5de985848503/bench_face_recipe_cloud_v2_20261026/BENCH_FACE_RECIPE_REPORT.html)

## 一、首先统一：N 到底是什么

**N 是实际送进模型的、非 padding 的总三角面数，包含输入 C。**

| 符号 | 含义 |
|---|---|
| \(N\) | 完整目标／生成状态中的总面数 |
| \(K\) | 输入条件 C 的面数 |
| \(F=N-K\) | 待生成的 free 面数 |
| \(S\) | 使用 SEAM 时，实际占用的 seam 面槽数 |
| \(B\) | bulk 面槽数 |
| padding 长度 | 为批处理补齐的张量长度，不是几何面数 |
| \(N_{\text{POST}}\) | 后处理保留面数，是输出统计，不是训练预算 |

因此：

\[
\boxed{N=K+F}
\]

使用你们的 SEAM 布局时：

\[
\boxed{N=K+S+B}
\]

**SEAM owner 是已有 free 槽位的归属和锚定安排，不能在 N 外面再额外加一次。** \(S\) 也应来自实际布局，不能直接等于 C 的所有边数；闭合 C 等没有适用 seam 任务的情况，继续按原合同处理。

还有一个容易混淆的地方：

> **free 面数与自由坐标标量数不同。**

seam 的部分角点固定在 C 上，因此 loss 分母应继续使用实际的自由坐标 mask，不能一律写成 \(9(N-K)\)。面数 mask、固定角点 mask、loss mask 各有用途。

### 一个具体例子

假设同一输入 C 有 40 张面：

| 目标版本 | N | K | free 面数 |
|---|---:|---:|---:|
| 原分辨率 | 420 | 40 | 380 |
| 合格低分辨率 | 300 | 40 | 260 |

这两个版本是两项真实的训练记录：它们必须分别拥有对应的目标几何、噪声槽位、mask 和配对信息。

不能只把第一条记录的 N 从 420 改成 300，也不能从它的目标里随意截掉 120 张面。

## 二、面数范围：模型容量保持 800，实际 N 按 21–799 执行

这次核对的官方实现是：

```yaml
max_length: 800
face_cond: true
face_bin: 20
```

但加载器实际接受：

```text
20 < N < 800
```

因此，这一版合同下的实际范围是：

\[
\boxed{21\leq N\leq799}
\]

这是当前代码的兼容范围，不是要求训练集中必须出现每一个整数 N。[官方配置](https://github.com/qiisun/MeshFlow/blob/cd7b47db3290e7483b0b782838bf4e13ccd440c5/configs/snet/base-120m-ot-v-bench.yaml) · [官方加载器](https://github.com/qiisun/MeshFlow/blob/cd7b47db3290e7483b0b782838bf4e13ccd440c5/datasets/mesh_dataset.py)

### 1. 面数不需要凑成 20 的倍数

模型的计数条件使用：

\[
b=\left\lfloor N/20\right\rfloor
\]

例如 N251 和 N256 使用同一个计数桶，但它们仍然有不同的真实槽位数。**桶是条件编码，N 是实际几何规模。**

因此：

- 实际得到 306 面，就记录 N306。
- 请求简化到 256，实际得到 306，不能记录 N256。
- 实际得到 124 面，不能为了符合旧范围把标签写成 N128。
- padding 到某个长度，不会增加实际 N。

### 2. N800 要单独处理

这份实现中，`800//20=40`，而计数嵌入的索引 40 用于 CFG 空条件；加载器也明确排除 N800。因此，不能因为配置里写着 `max_length=800`，就直接把 N800 当作普通训练目标放进去。[计数编码源码](https://github.com/qiisun/MeshFlow/blob/cd7b47db3290e7483b0b782838bf4e13ccd440c5/models/equidit.py)

对恰好 800 面的目标，当前处理应该是：

- 能在保持质量与 C 合同的前提下，重建成一个真实的 `<800` 版本，就按其实际面数准入。
- 做不到就暂存。
- 不随手删一面，不只改 N 标签。
- 扩展模型面数合同应作为另一项明确改动，不能靠改一个配置数值混进去。

### 3. 当前本地优先解决上限，低于 128 的兼容性单列

你们此前大量任务限制在 `N128–256`。**眼下优先级是允许合格的高面数目标进入，而不是同时强制启用所有低面数目标。**

自然 N64、N100 的完整 Bench 并不自动有问题；但它们能否进入你们当前的条件布局，要按实际加载器、owner 和 free 预算确认。可以保留为候选，不能用重复面填到 128。

## 三、数据应该怎么做：一个主版本，最多一个可选低版本

### 1. 主版本使用“合格目标的自然 N”

这里的“自然 N”指：

> **经过既定目标质量、C/Y 和语义检查后，实际准备送入训练的完整目标版本的面数。**

它不等于任意原始脏网格的面数，也不等于必须恢复作者资产中的所有冗余三角形。

处理顺序应是：

1. 确定完整目标版本。
2. 完成既定质量与条件任务检查。
3. 读取这个版本实际的 N。
4. 在模型合同内保留它，不因为超过 256 或 512 就排除父对象。

对之前因面数超限而暂存的目标，可以重新检查预算兼容性；**原本因为 C/Y 冲突、部件语义或目标缺陷而 HOLD 的条件，仍按原原因处理。** 放宽 N 不会自动让它们通过。

### 2. 不设统一的 256 或 512 几何上限

云端 56 个公开 TEST 来源，同时达到请求预算并通过原有限保真检查的数量是：

| 统一上限 | 合格来源 |
|---|---:|
| 256 | 16/56 |
| 384 | 31/56 |
| 512 | 45/56 |
| 640 | 53/56 |

这说明统一压低会排除或改变一部分来源。未通过既可能是未达到面数预算，也可能是保真不足，不能全部解释成“毁腿”。

所以，**需要 650 面才能保留完整结构的合格目标，就允许保留 650；本来 180 面已经合适的目标，也不需要扩成 512。**

### 3. 低版本是可选增强

每个条件任务族：

- 必须有一个合格主版本。
- 最多增加一个几何不同、通过检查的低版本。
- 低版本不合格，就只用主版本，父对象仍然保留。

本轮云端最终主分支是：

- 114 个父全部保留；
- 47 个父额外保留一个低版本；
- 67 个父只保留主版本；
- 合计 161 个版本。

**没有必要为了“多分辨率训练”，要求每个父都必须凑出两个版本。**

### 4. 低版本必须重新满足条件任务合同

这点对你们尤其重要。

云端检查的是完整物体的表面保真，没有 C 输入。落到固定 C 的训练任务，低版本还必须保证：

- C 的坐标、面和角点身份不变；
- C 与 free 目标的划分一致；
- 必需边界和接口仍然有效；
- owner、角色和固定角点 mask 对应新目标；
- 实际 free 槽位数为新 N 减 K。

**不能把整物无约束 QEM 的结果直接换进来，却继续使用旧 C/Y 划分和旧 SEAM 映射。**

暂时没有可靠的固定 C 简化方法时，就保留该任务的主版本。这不会阻止放宽 N、增加合格复杂父的主线。

## 四、“面数覆盖完整”应该覆盖什么

**重点是联合任务覆盖，而不只是 N 的直方图。**

至少同时看：

| 维度 | 为什么需要 |
|---|---|
| N | 完整输出的表示预算 |
| K | 条件自身占用多少面 |
| \(N-K\) | 剩余生成预算 |
| C 的类型与开放性 | 座面、支撑、组合、闭合部件的任务不同 |
| 结构关系 | 条板、端架、细腿、多部件等 |
| 独立父数 | 区分结构覆盖与重复版本 |
| 实际曝光 | 确认目录中的样本真正被训练访问 |

例如，下面两项任务都叫 N256，但难度和自由度明显不同：

- K20：还有 236 张 free 面。
- K200：只有 56 张 free 面。

同样，即使 N 和 K 都相同，薄腿、多端架与箱式主体也不等价。

因此，“38 个面数桶都出现过”只能证明计数范围有覆盖，不能证明这些桶中的条件关系都学好了。**增加同一父的 LOD，也不会增加独立父对象数。**

这和你担心的过拟合直接相关：25 个父即使各自做出很多面数版本，仍然只是 25 个独立父。

## 五、曝光怎么安排：父优先，条件其次，版本最后

推荐的抽样顺序是：

```text
打乱父对象，逐轮访问
    ↓
在该父内轮换条件任务族
    ↓
在该任务族内轮换主版本 / 合格低版本
    ↓
应用原有数据增强，执行当前训练合同
```

### 1. 从第一步全程混合

当前没有证据要求改成：

- 先低 N、后高 N；
- 先简单结构、后复杂结构；
- 训练后段才补高面数桶。

这次先采用全程混合，把“面数数据方案”与“课程顺序”分开。

### 2. 两个版本在任务内部按 1:1 轮换

有两个合格版本的任务：

```text
主版本 : 低版本 ≈ 1 : 1
```

只有主版本的任务：

```text
主版本 = 100%
```

**不是把整个数据池强行做成 50% 原版＋50% 简化版。**

云端实际 12,000 实例序列中：

| 项目 | 实际结果 |
|---|---:|
| 父对象 | 114 |
| 每父曝光 | 105 或 106 |
| 原有面数桶保留 | 38/38 |
| 全局低版本占比 | 20.61% |
| 平均 N | 419.17 → 388.31 |

这里的 1:1 是一个覆盖明确、易于解释的起点，尚未测出它是生成质量最优比例。

### 3. 不直接对所有 LOD 记录等概率抽样

否则，一个父有 7 个版本、另一个父有 1 个版本，前者就可能获得约 7 倍总曝光。

同样，云端先均匀选面数桶的模拟，会把每父期望曝光拉出约 6.75 倍差距，却没有增加覆盖桶。

所以，当前使用：

> **父曝光均衡，面数桶做监测；不通过稀疏桶反复放大少数父。**

### 4. 保留你们原来的增强单位

如果本地仍是“每步 4 父任务 × 两份尺度增强”，就先对父任务进行均衡抽取，再按原规则生成两份增强。两份增强继续共享本次选中的目标版本和 N。

云端演示的 105/106 是按单实例序列统计；不能不经换算就要求带成对增强的本地曝光也出现同样整数。这里要保持原训练合同，不顺手改变 batch 构成或增强倍率。

## 六、训练实现上，必须让 N、几何、mask 和 OT 一致

改变面数后，最重要的不是 YAML 里的上限，而是整条数据路径一致。

### 每条任务至少记录

```text
parent_id
condition_family_id
condition_id
variant_id
N_actual
K_actual
free_face_count
seam_face_count / bulk_face_count（适用时）
C / target / owner / mask 的身份与 hash
```

其中 `requested_cap` 可以另外保存，但不能代替 `N_actual`。

### 必须成立的关系

```text
实际非 padding 面槽数 = N_actual
C 面槽数 = K_actual
free 面槽数 = N_actual - K_actual
```

启用 SEAM 时，继续核对 seam/bulk 的拆分以及固定角点。

尤其要防止：

> 数据筛选已经放开到 799，但某个打包或布局环节仍然按 256 截断，计数标签却保留原 N。

### OT 与 loss 怎么处理

- 每个真实目标版本建立与其自身 N 相符的噪声和配对。
- C 不进入 free OT 的原合同继续保留。
- owner 固定与 bulk 配对继续按原规则执行。
- 不把低版本当作高版本的同槽截断。
- loss 继续按每实例的实际自由坐标数归一，再按原实例权重聚合。
- 暂时不增加按 N 加权的 loss，不同时改时间采样或学习率。

这样第一次比较才能回答“面数版本与曝光是否有用”，而不是又同时改变多个训练变量。

## 七、推理时 N 怎么选：与训练目标 N 分开

这是整套方案里必须单独说明的部分。

### 训练时：完整目标已知

训练任务有完整目标，因此可以合法使用它的真实 N。

### 真实 C-only 推理时：完整目标未知

只看到 C，通常无法唯一推出完整物体应该有多少面：

- 同一块座面可以完成成简单箱体，也可以完成成多条板长凳。
- C 自身三角划分密度不同，K 大不一定代表完整物体复杂。
- 不能简单用固定比例 \(N=K/r\) 来定义所有任务。

因此，当前建议是：

**把 N 保留为显式的推理参数，在已经覆盖且满足当前 C/layout 可行性的预算中使用。**

若启用 SEAM，还要满足已有 seam 占位和所需 bulk 的预算约束。不能指定一个连固定 C 与必要接口都装不下的 N。

这次实验没有训练“只根据 C 自动预测 N”的模型，所以：

- 不能把某个来源父的最佳简化面数，直接当作真实用户输入的已知答案。
- 不能把训练序列的平均值 388.31，解释成所有推理应设 N384。
- 不能把原论文容量 800，解释成所有推理应接近 800。

如果以后需要自动默认 N，可以研究只依赖 C 和真实训练分布的预算选择规则；当前先保持显式预算，便于解释和复现。

### 不通过增加 N 来补偿 D0 删面

假设 RAW 使用 N256，POST 只剩 100 面，这不能直接推导出“把 RAW 改成 512 就能恢复支撑”。

你们已经确认部分结构是在 D0 后被压细、再被 GEO 坍缩。**输入面数预算与后端保形是两个需要分别验收的环节。**

## 八、评价时怎么保证结果可解释

### 1. 旧面板继续保持原 C、N 和噪声合同

它回答：

> 面数训练配方改变之后，已有能力有没有改善或回退？

不能为了展示新方法，把旧面板的 N 一起调大。

### 2. 另设覆盖高 N 的固定面板

它回答：

> 新纳入的面数范围，是否真正学会了条件采用与完整生成？

各比较模型使用相同的 C 和指定 N。评价中提供目标对应的 N，可以作为“给定面数预算”的任务设定，但不能宣称模型已经能够自动预测 N。

### 3. 跨 N 比较另列

N 不同，噪声张量维度也不同。可以预先定义共同随机源或前缀规则，但不能声称两个完整噪声张量逐值相同，也不能把相同槽位当作同一语义面。

### 4. RAW 与 POST 分开看

继续保留你们已经建立的判断顺序：

- C 是否被主体采用；
- 主体与支撑是否完整；
- RAW 的 CF/FF/I 与碎片情况；
- D0/GEO 后保留了什么、损失了什么；
- 合法接口与可达性是否改善。

单纯增加保留面数、降低删面数，或降低某个冲突比例，都不能单独作为成功。

## 九、现在可以固定下来的执行规则

| 层面 | 当前决定 |
|---|---|
| 模型容量 | 保持 `max_length=800`、`face_bin=20` |
| 实际 N 合同 | `20<N<800`；当前本地低于 128 的布局兼容性单列 |
| 数据主线 | 允许已合格的高面数目标进入，解除统一 256 上限 |
| 主版本 | 使用合格完整目标的真实自然 N |
| 可选增强 | 每个条件任务最多一个合格低版本 |
| 低版本失败 | 保留主版本和父对象 |
| 固定 C | 坐标、面身份、角序及接口合同保持一致 |
| 面数标签 | 永远使用实际 N，不使用请求 cap 或 padding 长度 |
| 采样 | 全程混合；父→条件族→版本 |
| 版本比例 | 双版本任务内部约 1:1；单版本任务用原版 |
| 训练变量 | 初次只改变数据版本／曝光安排，其余合同保持 |
| 推理 | 显式传 N，满足 C 与布局预算，不使用未知来源 N |
| 评价 | 旧面板保持不动；高 N 能力另设固定评价；RAW/POST 分开 |
| 数据身份 | 沿用本地 split；公开演示清单不能直接开训，尤其保留本地 `df6` 留出 |
