# Bench 早期 FM 加权：1500 步配对实测

实验：`R2_BENCH_EARLY_FM_V1`，2026-10-22。训练、固定16请求采样、单次D0、完整CPU后处理与评分、16页实际截面图审均已完成。端点固定为1500步，没有挑选中间检查点。

**结论：本版早期时间加权没有扩大明确采用C的范围，不晋级为新基线。** USER与EARLY在熟悉条件上均为6/8明确采用，DEV均为0/8；RAW和最终POST的采用标签逐请求相同。POST的CF/FF有小幅改善，但DEV平均多删4.25张free面，小角率略升，若干靠背/座面出现更明显的表面缺失。不能把这些局部数值收益写成整体质量或泛化升级。

这也不是“早期阶段不重要”的结论。上一轮轨迹交叉表明熟悉条件的收益更依赖USER前半程；本轮检验的是一个更具体的实现：**在不改状态、数据和网络的情况下，增加低t的原FM权重，能否把这种重要性转成更好的生成。当前答案是没有形成所需收益。**

## 1. 问题、历史边界与实际改动

前轮[真实轨迹交叉](../r2_bench_trajectory_crossover_v1/REPORT.md)中，USER前缀保住了熟悉支撑与组合条件的采用收益，但四种组合的DEV均无明确采用。因此本轮只增加一个配对训练臂，直接对照已完成的USER v2，不再次训练普通对照。

相近历史路线已经查过：R02涉及条件注入/时间设置，R07/R19涉及其他辅助目标；Bench [PERT/ASYNC](../r2_bench_state_schedule_v1/REPORT.md)分别改变训练状态/目标或seam角点完成时间，均不同于本轮。这里没有重命名它们，也没有增加读取模块、RL、局部吸附loss或另一个去噪器。

| 固定项 | 本次实际合同 |
|---|---|
| 初始化 | 与USER v2完全相同的 `A_COMMON_LR1E5/checkpoint_step0.pt`；已有COMMON12000历史，fresh AdamW与相同RNG |
| 训练池 | USER v2的25个TRAIN父、81条已准入条件；DEV不入训练 |
| 输入流 | 同一1500更新、12000实例的父/条件/N/增强/时间/随机流；逐条核对一致 |
| 生成器 | Native/T1 + role + Geo + SEAM，130,401,155参数；未增加参数 |
| 匹配与噪声 | 原受限OT，随后HYBRID 0.25；原角点掩码、来源owner训练布局 |
| 优化 | batch8、microbatch1、lr=1e-5、AdamW betas=(0.9,0.95)、weight_decay=0、clip_norm=1 |
| 精度 | BF16前向、FP32参数/积分；确定性算法strict、TF32关闭、SDPA math、原CUBLAS配置 |
| 预算 | 新增1500更新，累计global13500；仅预定终点作为主结果 |
| 唯一科学变量 | 原FM贡献按flow-time加权：t<0.5乘1.5，否则乘0.5 |

不是训练前750步采用一种loss、后750步换另一种。**整条1500更新都使用同一个按采样时间t分段的权重。** 也不是从USER最终权重再接着训练1500步，更不是从官方预训练重新训练整个COMMON阶段。

设第i个实例的可动坐标集合为M_i，保持原整个batch的坐标分母D：

\[
L_{\mathrm{EARLY}}=\frac{\sum_i w(t_i)\sum_{j\in M_i}(v_{ij}-u_{ij})^2}{D},\quad
D=\sum_i|M_i|,\quad
w(t)=\begin{cases}1.5&t<0.5\\0.5&t\ge0.5.\end{cases}
\]

未在单个microbatch里除以权重，否则microbatch1会把改动抵消。原t采样是`sigmoid(N(0,1))`，不是均匀分布；分布对称使总体E[w]=1。实际冻结流为5994个低t、6006个高t，实例平均权重0.9995，坐标数加权平均0.99890355。梯度大小并不因此严格相等，clip次数也有变化，见第3节。

实现差异保存在[training_change.diff](training_change.diff)。初始化生成器/优化器hash一致，第一批8个前向统计逐位一致；12000条曝光身份一致。后续模型按不同目标正常分叉，不声称不同权重结果应逐位相同。

## 6. 这轮支持什么，不支持什么

1. **支持有限的数值交换**：低t seam训练误差略降，最终CF/FF局部改善；同时高t拟合变差，部分输出表面覆盖减少。
2. **不支持当前候选升级**：明确采用范围不变，DEV失败仍在，阈值成功数的唯一增加是既有好例轻微跨线。
3. **不推翻轨迹前缀诊断**：前半程对布局重要，不等于提高训练插值路径低t权重就能改善自主生成。正常训练前向与rollout访问的状态分布仍不同。
4. **不证明数据是唯一根因或所有时间方案无效**：正权重仅依赖t时，在无限容量、充分优化的条件下，不改变固定t的理想平方损失回归解；它改变有限训练中各时间段的优化分配。本轮只检验1.5/0.5、1500步这一项，不扫权重、阈值或更长预算。

**下一步优先判断应回到失败几何关系的覆盖，而非继续扫描本版时间权重。** 一个明确待检验假说是：补充与失败C相近、但具有不同合理主体相对布置的训练条件，能改变未见父的RAW采用；仅重新分配相同81条条件的监督时间不能做到。该假说尚未被本轮证明，不能把它写成“已经确定只需加数据”。若后续测试，应固定模型、训练预算与旧好例回归，并以新父RAW采用及主体表面保留判读。本轮不自动启动。

## 7. 实际计算、并行与工程账本

| 阶段 | 实际执行 | 调用/时间 |
|---|---|---|
| 正式训练 | 1进程，1500更新 | 12000前向、12000反向；2140.584秒（35.68分钟） |
| 固定噪声采样 | 两个8请求shard，逐个启动且实际重叠 | 共800生成器前向；装载后采样/保存循环各44.896、44.213秒 |
| 官方D0与基础整理 | 16请求各一次；全部RAW保存后开始 | 16 D0前向；阶段50.125秒，含装载/整理 |
| RAW原评分 | 3个CPU进程 | 16份、19.588秒，与D0阶段有重叠 |
| POST完整CPU链 | 3个CPU进程 | 16份、108.546秒 |
| 对照图 | 2个CPU进程 | 16页、64个实际图审单元；未额外调用模型 |
| 汇总 | 原COMMON/USER96行 + 新EARLY48行 | 144行、178个原数值字段，逐请求/逐父完整保留 |

新增神经网络前向总计12816；反向12000；优化器更新1500。新增占用头/教师特征探针调用均0，新增评价噪声0（训练使用与对照相同的固定随机流），模型失败、GPU重放、超预算训练均0。上述采样并行耗时不能与孤立运行直接作效率benchmark，也不能把重叠阶段耗时简单相加当总墙钟。

资源在开训及每个GPU调度波次前核验：RTX5080，16303MiB；24个逻辑CPU；初始可用RAM约65.5GB。训练实际覆盖前向、反向与AdamW，设备用量采样峰值5185MiB，PyTorch reserved峰值3311403008字节。NVIDIA-SMI未提供可归属进程显存，因此设备峰值明确包含后台占用，不能冒称单进程峰值。两采样进程重叠时记录设备使用3555MiB；首个实际请求后才增派第二进程，保留至少2GiB额外余量。只存在一条授权训练臂，不能为并行另开训练对照。未停止用户其他进程，数值CPU线程限制为1。

工程准备阶段有两项已留痕修正：比较原t时按原FP32存储口径核对，且适配16请求的split字段；评价包装器补齐原清单中的part_family/closed_C报告元数据。后者在本轮采样/评分前修正，旧包装源码和旧登记均保存在`engineering/`，不改变任何几何、模型输入或评分定义。另一次监控命令语法错误未执行任何任务，随后使用独立monitor入口。没有借修复静默重跑GPU。

所有48条模型×请求保存的轨迹均核验51状态、50次Euler更新、同一初始数组、全程锚点精确保留和RAW端点一致；所有144条评分检查C精确保留与原角序。官方/历史权重、原评分器、数据和旧结果按登记hash复核。以上是本轮检查边界，不是承诺任意环境逐位复现。

D0资源快照的设备用量最高记录为3796MiB，含后台占用；这是所存阶段快照最大值，不是高频采样得到的连续进程峰值。训练、采样、D0的内存口径分开保存在原资源JSON中。
