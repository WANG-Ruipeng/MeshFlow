# C-only owner 布局头：冻结前独立核对

2026-10-17。范围为已有 TRAIN47 标签、旧头源码/日志、R31 历史与最新冻结布局实验。仅 CPU NumPy 读取缓存，没有导入模型、头前向、生成器前向、训练、重评分或改写旧文件。小查询的完整计数见 [readonly_label_review.json](readonly_label_review.json)。

**支持在冻结生成器的前提下单独验证布局头。** 最新 B→LONG 布局反事实已证明布局是可干预且影响生成的因素；但“旧头太小”“只有训练不足”“换损失就能解决 DEV”等都尚未成为独立因果结论。本轮应当检验一个固定、可部署的 C-only owner 决策模块，不把来源布局分类正确等同于开放生成成功。

## 1. 标签到底是什么

实际构造先查来源合法 C/Y 共边。同一个 Y 三角面若对应多条 C 边，以最小 `source_edge_id` 为唯一 owner；其余边为 alias，不再占一个新的独立三角槽。没有来源合法邻面的边才是真 Null。[b_pool.py](../../r2/pilots/seam_abc_v1/b_pool.py:77)

| TRAIN47 标签 | 数量 | 本轮 owner-active 二分类目标 |
|---|---:|---:|
| 独立 owner | 360 | 1 |
| 同一来源面的 alias 边 | 6 | 0 |
| 无来源合法邻面的真 Null | 34 | 0 |
| 合计 | 400 | 360 正 / 40 负 |

不能把 366 条来源支持边全当 366 个独立 seam 槽；也不能把 40 个负标签统称 40 条“不应该连接的边”。源完成只是合法的一个完成，真 Null 表示该来源没有合法邻面，不证明任意合理生成都必须在那里开口。源分类指标用于检验布局学习和与旧生成器训练布局的相容性，不取代开放生成任务评价。

六条 alias 分布在四父：5420 的边9→owner2；893c 的9→7、10→8；9715 的4→2；b192 的7→5、9→2。六条对应的 owner 第三点都属于 C；总计12个 owner 的第三点属于 C。旧 B 表示仍把这些第三点作为自由变量。[ABC 原报告](../r2_seam_abc_v1/REPORT.md)

因此本轮若继续输出一个 owner-active boolean，应该称为“owner 布局头，按 owner/alias/真 Null 分层审计”，而不是已经实现 alias 指针或 C 第三点引用。alias 预测 inactive 只是避免重复分配独立 owner 槽，不会自动使生成第三点落回正确的 C 顶点或修好 alias 接口。本轮不改变这些生成器/解码语义。

## 2. C-only 可辨识性：本池无直接冲突，不能据此承诺唯一解

独立查询47份已有 `C_only.npz` 与训练标签：

- 相同完整 C-only 数组（含 N）的重复组：0。
- 忽略顶点/面编号、按精确坐标的无向三角集合比较，完全相同 C 表面的重复组：0。
- 400 个原24维边特征的精确重复组：0，因而也没有检出相同24维向量却标签不同的训练行。

查询使用精确 FP32 值，不含近似聚类或相似性阈值；未发现冲突并不等于证明存在可泛化的确定性映射。一个相同 C 可以有不同合理 Y：某条边在一个完成中有邻面、另一完成中开放；两个 C 边也可能在一种完成里属于同一 Y 面，在另一完成里各自有不同邻面。这些未知关系不能由“当前每父仅一个来源版本”排除。

owner 是对来源 Y 的去重分配约定，最小边 ID 又依赖 C 的编号/排序。加入 `boundary_rank/(E-1)` 可以表达这个约定的一部分，但不能提供未知的 Y 邻接信息。该 rank 来自 C 本地拓扑，不是原父 ID；仍需明确对任意顶点重新编号不保证不变。全边上下文可以表达边间关系，不能保证消除所有源布局歧义。

## 3. 旧头并非“只学了200步”，也不能把旧权重当代码错误

旧头是24→32→1 SiLU MLP，共833参数，不是线性分类器。B 从 SEAM200 恢复头和独立 AdamW，又训练800更新、6400实例；不是重新随机初始化一个头，只学136次。[occupancy.py](../../r2/src/meshflow_control/seam/occupancy.py:19)、[实际恢复代码](../../r2/pilots/seam_abc_v1/training/train.py:316)

真实日志核对：43父各136次、4父各138次；原四父还在最初SEAM200阶段各有400次曝光。B阶段合计正边49014次、负边5442次。曝光与更新应分开报告，不能把每父136次当136个优化器更新。

旧损失显式使用负类8.25、正类66/124≈0.53226，按批内全部有效边平均；它从原四C的62正/4负继承，47池没有重新计算。这是已冻结的旧定义，不是正负顺序写反。新47池的360正/40负若按同一逆频率公式重算，权重应为负5、正400/720≈0.55556；但这不证明重新平衡优于不加权。[旧训练损失](../../r2/pilots/seam_abc_v1/training/train.py:185)

在理想无限容量且精确优化的加权BCE下，logit会偏移 `log(w_pos/w_neg)`；旧权重比15.5对应原始后验阈值约0.9394。有限网络并不严格服从这一解析校正。此前加 `log(15.5)` 恰好变成全占用，丢掉4/4真Null，已经证明不能直接称为“校准修好”。[R31后续记忆](../../r2/docs/research_route_memory.md:29)

旧 B 最后100更新的动态训练日志：TP2776、FN3326、TN506、FP148；owner召回45.49%、负类特异度77.37%，完整布局57/800。它说明当前已执行配方确实存在布局拟合缺口。这些行来自不同训练时刻、部分宽度增强输入，不是冻结最终模型的47父测试，也不能单独区分容量、损失、优化和曝光因素。

旧头与生成器参数/优化器独立，特征detach，BCE不回传到生成器；生成器训练使用来源owner布局。因此单独换头可以隔离推理布局的作用，不能声称本轮会继续提高生成器本身的FM拟合。

## 4. 对拟冻结小预算的意见

以下是冻结前建议，不是已经运行的结果；最终以根 `PROTOCOL.md` 和登记文件为准。

| 项目 | 固定建议 |
|---|---|
| 数据 | 现有47 TRAIN、400边；不读取DEV训练标签优化参数，不加父、不改源面 |
| 两头 | 同26维C特征（原24+边rank+E/32）；897参数MLP对照与2层、宽32、4头context候选 |
| 参数与优化 | fresh独立AdamW，lr1e-3、wd1e-4；共同固定种子政策、完整确定性运行；生成器零更新 |
| 损失 | 每父先对有效边做unweighted BCE均值，再对47父平均；记录真实分母 |
| 预算 | 每头固定2000更新，固定最终权重；若每更新全47父，则每头94000父实例、800000边曝光；头前向调用次数另按实际批处理记账 |
| 主候选 | 预先选context；MLP作为同预算诊断，不按结果择优替换或回退 |
| 决策 | sigmoid≥0.5（等价logit≥0）；不扫阈值、不挑checkpoint、不自动续训 |

这同时改变旧头的输入、优化目标、fresh状态、曝光量和（候选臂的）上下文结构，所以只能把对旧头的收益归给“这套独立布局模块”；不能只归因于加宽或全局attention。新MLP与context可比较上下文结构在相同新训练合同下的作用。

建议TRAIN门槛：owner recall≥90%；34真Null的specificity≥80%；6 alias的inactive比例≥50%；四熟悉父分别owner recall≥90%。**另建议四熟悉父的4条真Null全部inactive**，否则总体80%允许3f/8c的4条已知Null全部被误激活，仍可能重演已知I尾部。只报accuracy不足：全激活已能得到360/400=90% accuracy。

DEV只在最终冻结后做一次布局否决检查，不据此调阈值或再训练：各父owner recall≥90%（13中至少12、4中4、3中3）；唯一真Null不能激活；2d的3 alias至少2条inactive。小分母必须同时给计数。这是本轮有限生成预算的准入规则，不是统计显著性或一般化定理；DEV已被历史多次观察，不能称全新盲测集。

若固定主候选不通过，不用MLP补位，不换门槛，不偷偷生成来源oracle。若通过，才执行用户已授权的冻结LONG/B各28请求、同C/N/旧噪声、单次D0和固定1.5%绑定。各阶段分开保存：原布局缓存、仅新布局POST、同一新布局POST加绑定；否则无法区分布局和绑定各自贡献。既有绑定代码需先补强已知“排队LATERAL当前tip根变C”的保护并登记新hash，不能以旧112例未触发推断新布局不会触发。

## 5. 与历史路线的关系及验收边界

最近路线是R31占用失配、SEAM几何保护的解析去权重全激活、ABC的47父占用头和最新冻结B布局替换。真正的新证据是同一B生成器只换LONG布局，熟悉TRAIN主体可达≥30%从4/16到12/16；但DEV仍0/12，I/小角等代价保留。[最新冻结报告](../r2_seam_followup_v1/REPORT.md)

本轮实质变化是把头独立优化为可核验C-only owner布局模块，并固定一次生成验证；不是再延长生成器、重跑RL、恢复旧指针或推断全占用一定更好。保留原完整指标、RAW/POST分离、逐父配对与实际AI_PROXY图审。来源布局更准也必须经过实际生成：能否保住接续、FF/CF/I、小角、删面、表面积与主体完整性，仍由这些产物共同判断。

独立只读查询输入为原 `B_DATA_REGISTRATION.json`（SHA256 `7609dbd1217d93684aa2d49ae11e1387a047bbfb14646924b7f371b19249093f`）、47条登记C/label数组及原 `training/B_POOL47/occupancy_training.jsonl`。查询没有读取DEV用于筛选特征或阈值，没有新评分或头前向；输出计数仅用于此冻结前解释核对。
