# Bench 数据输入合同：先 C，后 Y

本目录是2026-10-22的CPU数据建设。SHIFT交叉保持关闭；没有训练、生成器、占用头或D0前向。旧资产、原结果和模型保持只读。

输入阶段只允许读取用户C的坐标、连接、原角序及可逆规范化元数据、显式请求N、冻结的生产布局规则。父ID、完整Y、source-owner和部位语义不得参与输入布局决策。部位名称只供构造和评阅。

1. 完整目标M必须先通过完整性与适用的几何检查，C/Y来自同一版本、同一坐标变换。
2. 在读取Y做匹配前冻结生产布局及其输入签名。旧缓存必须精确匹配C/N/角序，不能按父ID近似复用。缺少缓存不以source-owner补齐。
3. 每个激活seam槽分配一张含该锚边的原Y面；每张Y面最多使用一次。未选中的原接口面可以完整进入bulk。
4. 剩余原Y面全部进入bulk，逐面身份及坐标一一往返；总N不变。禁止复制seam、制造连接帆、删除难面或用退化槽填数。
5. 多槽竞争同一面、或激活边没有任何对应原面时，明确标记布局/目标不兼容。不能用Y静默关边再称为C-only。
6. 合法owner合同与一般端点几何可表示性分开记录。前者失败不自动意味着数学上无法表示；反之能表示也不认证合法接合。
7. 数据增强顺序尚未冻结。未增强C的旧预测不能冒充变换后生产头的预测。将来应在“生产规则前/后变换”的明确合同下统一训练和部署。

执行实现为`r2/data_tools/bench_deployment_tasks_v1/layout_contract.py::compatible_endpoint`。本轮已在既有缓存上实际完成确定性端点打包及反例检查；不包含新OT、随机流或训练。

## 当前证据

- 当前26父91C：source-owner直接改变锚点掩码、起点、轨迹、角点role/time与FM有效分母。不是只影响loss末端的等价换序。
- 91C中只有4条有精确生产缓存，2条闭合C无需头，85条缺缓存；4条缓存中3条模型可见角色不同。
- 838c组合条件误激活的两条边没有对应原Y邻面；忠实一一编码失败，保留原件与失败证据。
- 实际旧48请求的24个C：11布局相同、13不同；DEV16个C全部能按合法owner合同表示来源目标。因此不能把本次发现直接称为DEV失败根因。
