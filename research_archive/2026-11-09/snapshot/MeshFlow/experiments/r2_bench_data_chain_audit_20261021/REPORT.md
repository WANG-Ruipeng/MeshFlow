# Bench 数据链与覆盖核查

2026-10-21；CPU 实际读取核验。当前主线为 Bench 的整体生成质量、条件采用与泛化。

**数据链中存在两个可定位的问题：目标包含重合双面表达，接口资格筛选又缩小了真实部件任务的覆盖。但这些都不足以解释全部坏例。** 当前证据支持重建条件覆盖后做固定预算训练，不支持直接把有重复面的父全删掉，也不支持宣布网络因素已排除。

## 1. 实际检查范围

读取原72父、316条件的完整来源与配对数组；当前活动训练为58父195条件，DEV为8父39条件。核对三个最新实验臂的实际曝光流，连接432条既有逐输出结果；实际另看6页来源/生成图片及截面。归档库存额外读取560份Bench NPZ，仅在内存检查，没有解压、修复或重新评分完整相交。

本核查零模型加载/前向、零训练、零生成、零OT。原数据、评分、图审与报告只读。精确重复和零面积检查是基础描述，不认证无自交、流形或完整性。执行与哈希见同目录账本。

## 2. 当前训练目标确实有重复表达，且部分跨越C/Y分区

| 核查项 | 当前TRAIN |
|---|---:|
| 父/条件 | 58 / 195 |
| 完整M含同源顶点ID重复面 | 39/58父，909张额外副本 |
| 上述重复面对绕序 | 909反向，0同向 |
| 完整M含精确零面积面 | 29/58父，164面 |
| Y内部有重复面 | 128/195条件 |
| C整张三角形在Y中有精确重合副本 | 41/195条件，18父 |
| 同时没有精确重复和零面积 | 15/58父，仅47条现条件 |

重复的定义为同一无序源顶点ID三元组；额外副本为组内数量减一。另以存储坐标的精确相等独立检查，本批没有额外的“不同ID但同坐标”重复。反向绕序是实测，作者是否有意表达双面薄壁没有被认证。不能把这些面全部认定为无意义垃圾。

41条C/Y重合条件共有118对反向面；该数跨条件重复使用来源几何，不是118个独立父缺陷。源面ID互斥、C+Y逐位恢复M仍然全部通过。因此，**分区代码正确，不意味着Y没有在几何上重复C**。

三臂相同12,000次曝光中，7,916次（65.97%）的Y含精确重复面；5,996次（49.97%）含零面积面；2,500次（20.83%）出现上述C/Y重合。这三组重叠，不可相加。它们说明这种监督不是极少数偶然样本，但没有证明某一次生成错层由此导致。

DEV只有一个父的三条条件具有C/Y精确重合，固定评价面板仅其中一条、两份输出。多数DEV错层不能由这一精确重复现象单独解释。部分共面覆盖、近重层和真正穿插本轮为NOT_RUN。

## 3. CLEAN筛选在选择接口任务，不是清洗完整目标

实际筛选是`B_c>0且至少一个来源owner`。来源M和全部保留行与原件一致，没有做目标去重或修复。

| 类型 | 原训练条件/父 | 当前条件/父 | 最新曝光占比 |
|---|---:|---:|---:|
| 座面 | 58/57 | 48/48 | 32.13% |
| 腿/支撑 | 98/49 | 41/23 | 12.63% |
| 靠背 | 17/17 | 16/16 | 7.67% |
| 部件组合 | 43/42 | 35/34 | 19.30% |
| 座面＋支撑 | 47/47 | 42/42 | 21.27% |
| 座背 | 12/12 | 11/11 | 4.72% |
| 其他 | 2/2 | 2/2 | 2.28% |

原277条件/64父缩到195/58，排除44条闭合C和38条开放但无来源owner的C。腿类占排除项57条，父数49→23。当前训练没有闭合C，固定DEV仍含3条闭合C、6份输出。COMMON12000曾见过这些任务，因此这是**最新适配阶段的覆盖变化**，不能说模型从来没有见过。

82条排除任务曾占COMMON曝光24.17%；腿类曝光从20.63%降到12.63%。当前每父206–208次，单条件16–208次、中位52次，符合父均衡后部位/变体轮转规则。三臂实际日志与冻结流完全一致，没有发现采样错位。

现有`part_type`粗分组包含不同范围：一条座板与完整座面、腿侧表面与完整端架并不等价。18条历史文件名与修正语义不同，但代码使用修正字段，不能当作标签读取bug；部位名字不输入模型。

## 4. 覆盖不足有具体例子，也有重要反例

- `9d5608`历史SEAT条件实际是靠背水平顶盖。训练有一个相似类型的顶盖父，不能说完全没见过；DEV厚度方向跨度0.151763，训练同类最大0.073204，现有±8%增强未覆盖。
- `fd355`支撑C中心Y为−0.307062，训练腿类最低−0.208330，原点缩放到1.08倍也未覆盖。
- `459f90`闭合座板＋弯曲端架占源表面积65.30%，当前同类最大46.09%。面积分母包含来源重复面，不能直接当无重叠覆盖率。
- **16条正式DEV条件中仍有8条在所查8个粗描述量的训练范围内。** 边界范围不是高维语义覆盖认证，也不支持用OOD解释所有失败。

实际重看来源与同位置截面：`9fd5b6`的完整来源没有本轮检测到的重复/零面积面；完整U形端架条件能有合理用途，而同父座板条件仍出现蓝板与灰座面错层。`459f90`来源同样通过这两项检查，其大面积、连贯的蓝座板＋端架仍在灰色上层碎板下方。它们否定“只要去掉精确脏面就必然成功”，也否定“坏例都是输入太碎或太少”。

既有A终点DEV记录中，通过两项源检查的3父12输出仍有5份C被替代/忽略、7份层叠；其余5父20输出有7份被替代/忽略、15份层叠。这里只展示反例，父类型和输入不同，不作因果或显著性推断。所有既有图审为非盲AI_PROXY；新增6页观察单独记录，不冒充重新审完432项。

## 5. 本地还有多少可用来源

只读`shapenet-cls.tar.gz`：Bench类别为02828884，560份NPZ对应560个不同UID，每UID只有一个现成版本。

| 面数区间（含端点） | 父数 | 同时无同源ID重复、无精确零面积 |
|---|---:|---:|
| 20–127 | 51 | 11 |
| 128–256 | 88 | 21 |
| 257–400 | 101 | 13 |
| 401–800 | 320 | 40 |

当前128–256范围剩16个未选父，只有3个通过两项基础检查；这不等于其他13个都应删除，也不保证这3个都能构造有效部件。更高面数还有421父、53父通过两项检查；其中N=800有5父、2父通过。官方加载条件严格N<800，不能把这5个直接算入原加载器可用量。

官方Bench配置`max_length=800`，加载器采用20<N<800；我们现行Native/SEAM接口则有128–256的硬校验。**官方骨干的范围不等于当前条件系统已经支持同一范围。** 本地归档每UID一个版本，也不能凭论文增强方法声称本地已经有低失真多面数版本。[官方配置](https://raw.githubusercontent.com/qiisun/MeshFlow/master/configs/snet/base-120m-ot-v-bench.yaml)、[官方加载器](https://raw.githubusercontent.com/qiisun/MeshFlow/master/datasets/mesh_dataset.py)

MeshXL对简化另检查几何/渲染保真；MeshPad把裁剪操作分布作为训练任务的一部分，且还有草图输入。这些支持“完整目标保真”和“输入任务覆盖”分开检查，不支持拿论文预算保证本地扩池必胜。[MeshXL数据处理](https://arxiv.org/html/2405.20853v2#S3)、[MeshPad数据构造](https://arxiv.org/html/2503.01425v4#A2)

## 6. 后续决定与边界

用户已进一步授权扩充数据并实际训练一臂，确认预算1,500步、固定48请求。本轮后续独立建档于`../r2_bench_coverage_expansion_v1/`：先维持N128–256及现有模型，恢复合理闭合/无owner部件任务，核验16个未选来源的部件候选，冻结实际数据后训练。原始几何和薄片表达保留，不同时引入去重、面数修改或新loss。

检验假说是：**当前接口资格筛选及较窄的部件实例覆盖，参与了后训练后的条件采用不足；补充这些任务后，在同初始化、优化设置和更新预算下，固定DEV的采用/错层是否改善且质量代价可控。** 一臂整体数据策略变化不能单独证明新增父、闭合C或某个部位是唯一原因，1,500步也不能认证覆盖已经充分。

Chair的历史DEDUP与匹配N负结果仍有效，不因这次发现反向重复而自动重做去重训练。已有8DEV多轮复用，不称独立新测试集。后续训练记录与本CPU核查分开计账，本报告不包含尚未产生的训练结果。
