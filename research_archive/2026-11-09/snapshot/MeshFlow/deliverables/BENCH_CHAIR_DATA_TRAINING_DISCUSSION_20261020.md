# MeshflowCrtl：Chair 与 Bench 的数据、训练历史及泛化问题

核对日期：2026-10-20。用途：提供给网页版 GPT，讨论下一轮 Bench 训练配方。本文整理已有实验，不启动新训练，不预先认定失败根因。

**当前判断：Bench 值得重新评估后训练配方，不能继续把“达到 Chair 相同步数”当作训练充分或泛化良好的保证。已有固定探针显示训练拟合改善而 DEV 误差恶化；但 Bench 的后训练父数并不比 Chair 少很多，任务种类、预训练数据、历史曝光和评测划分也不同，不能把全部问题归结为“小数据配大模型”。**

## 1. 我们要解决什么任务

我们从官方 MeshFlow 类别专用预训练生成器出发，增加真实三角面条件控制：

- 输入：给定三角面集合 C，包含坐标和连接信息，以及总面数 N。
- 输出：保留 C，生成剩余 free 面 F，形成合理、多样的完整物体。
- 目标：C 被合理采用，并在适用位置接入生成主体；整体表面尽量完整，减少穿插、重层、碎片和异常删面。
- 不要求恢复唯一来源父对象的款式。来源完整网格用于构造训练配对和监督诊断，不是开放生成的唯一正确答案。
- 当前面数范围 N=128..256。真实输入偏向连贯、规则的部位面片，K≥2。

普通条件模型为 Native/T1＋role＋Geo，采用 free-only Flow Matching、OT 后 HYBRID 0.25。SEAM 在此基础上增加共享原边槽：激活的 C 开放边对应一个 seam 面，前两个角点固定引用 C 边端点，学习第三个角点；其余面仍作为 bulk 自由生成。训练使用来源 owner 布局监督，推理使用只看 C 的布局预测。

采样为标准 Gaussian 起点、Euler50；之后单次官方类别 D0 去噪、恢复 C／seam 锚点、GEO_C、来源角序恢复与固定 C 的 free 定向。另有已验证的 CPU 接续后处理 HINGE_OPP015、ALPHA、HOLE，结果必须注明具体阶段。

## 2. 数据规模：必须区分四种计数

“独立父 UID”“同一父的不同网格版本”“不同条件 C”“训练重复曝光”不是同一种数据量。

### 2.1 官方预训练数据与本地资产

| 口径 | Chair | Bench | 如何解释 |
|---|---:|---:|---|
| 论文报告的增强后类别网格数 | 80,569 | 13,142 | 简化得到不同面数版本，不是独立物体数 |
| 本地官方 class 归档中的父 UID 网格文件数 | 3,135 | 560 | 包含 train/test；UID 去重不等于几何完全去重 |
| 该归档官方 train 划分条数 | 2,822 | 504 | 实际读取 split NPZ 数组形状 |
| 该归档官方 test 划分条数 | 313 | 56 | 不参与本地训练父池的常规扩展 |

论文采用不同面数的简化增强，并报告上述增强后数量。[MeshFlow 原论文第 5 节](https://arxiv.org/html/2606.23489v2#S5)

本地来源为 `downloaded_data/archives/shapenet-cls.tar.gz`，划分来自归档中的 `split/train.npz`、`split/test.npz`。这些计数不能证明官方检查点逐一见过哪些 UID；没有官方训练曝光日志时，精确曝光身份仍为 UNKNOWN。论文增强数量也不能直接当作本地可用于 N128..256 条件构造的合格父数。

Bench 的官方增强网格数约为 Chair 的 16.3%，本地父 UID 数约为 17.9%。这说明数据规模差距存在，**尚不能据此推出 Bench 官方先验必然更差，或本地失败主要由该差距造成。**

### 2.2 本地后训练真正用了多少数据

| 阶段／任务 | TRAIN 父数 | TRAIN 条件数 | 条件范围 |
|---|---:|---:|---|
| Chair EXP67 | 67 | 194 | 座面／靠背 FULL、HALF，去重后的 USER 条件 |
| Chair FULL 与后续主要 SEAM 池 | 47 | 47 | 每父一条合格完整座面；24条为 K=2 |
| Chair SEAM 最初快筛 | 4 | 4 | 四条熟悉完整座面，集中曝光 |
| Bench 原多部位训练 | 64 | 277 | 座面、腿／支撑、靠背及多部件组合 |
| Bench 最新 CLEAN 训练 | 58 | 195 | 从277条中筛选有有效来源 owner 的条件 |

Chair 的47条来自 TRAIN67 原有50条 FULL，准备时排除了3条多连通 C。Bench 原活动池连 DEV 共316条：座面65、腿／支撑107、靠背22、座面＋支撑54、座面＋靠背16、多部件组合50、其他2；其中 TRAIN277、DEV39。

Bench 全316条中有49条闭合 C、90条多连通 C、167条非平面 C，K=2..162。其任务复杂度与 Chair 后期的单一完整座面池明显不同。

Bench CLEAN 排除的是 TRAIN 中44条闭合 C 和38条开放但无有效 owner 的条件，保留195条／58父；仍包含69条多连通条件、41条腿／支撑条件。**“CLEAN”在这里是有效接口条件筛选，没有清洗来源自交、重复面或修复完整目标几何。**

因此，后训练数量的准确比较是 **67／47 个 Chair 父 vs 64／58 个 Bench 父**，而不是“Chair用了几千把，Bench只用了几十把”。几千与几百是另一层的官方资产规模。

### 2.3 DEV 划分也不完全对等

- Chair EXP67：32个 DEV 父、64条 C，来自官方 train 来源；与本地条件训练父隔离，但不能宣称官方预训练完全未见。
- Chair 当前 SEAT 主面板：4个熟悉 TRAIN 父×4噪声=16请求，3个 DEV 父×4噪声=12请求，共28份。
- Bench：8个 DEV 父、39条候选条件；7父来自官方 test，1父来自官方 train 但未进入本地条件训练。
- Bench 固定评价：4 TRAIN 父和8 DEV 父，每父2条 C、每 C 2噪声，共48请求。TRAIN16、DEV32；其中开放 C 请求分别14、26，闭合 C 的 seam 接续字段为 NA。

Bench DEV 包含更多官方 test 父，Chair 强正结果则主要来自反复观察的熟悉座面。因此现有成绩不是严格的跨类别泛化难度对照。

## 3. 模型大小和真实训练历史

### 3.1 参数与初始化纠正

本地条件生成器实际为 **130,401,155 个参数，约1.304亿**。约521.7 MB是FP32导出文件大小，不能称为5.2亿参数。论文报告的基础架构为124M；这里以本地检查点审计数量描述实际条件生成器，不将二者差额未经核算全归给某个新增模块。

Chair 和 Bench 的网络规模相同，分别继承官方 Chair／Bench 生成器 EMA。首次条件训练使用 fresh AdamW；“从0开始”指条件适配 global_step=0，**不是从随机权重训练完整生成先验**。后续阶段恢复对应 live 生成器和匹配优化器。

两者都是全参数条件适配，不能因继承了预训练模型就排除小数据过拟合风险；也不能只用“参数数÷父数”推断哪一类必然过拟合。官方类别先验、任务跨度、更新强度和数据覆盖都参与其中。

### 3.2 Chair 当前保留生成器 PLAIN_S2000

注意：名字里的 PLAIN 表示这条 SEAM 分支没有新增 couple 等辅助项，**它仍然是 SEAM 生成器**。

| 顺序 | 训练池 | 新增步数 | 累计条件步数 | 本阶段实例曝光 |
|---|---|---:|---:|---|
| EXP67 | 67父／194C | 6,000 | 6,000 | 48,000；每父716–717次 |
| FULL_S6000 | 47父／47完整座面 | 6,000 | 12,000 | 48,000；每父1021–1022次 |
| SEAM_SLOT_C200 | 4父／4完整座面 | 200 | 12,200 | 1,600；每父400次 |
| B_POOL47 | 47父／47完整座面 | 800 | 13,000 | 6,400；每父136或138次 |
| PLAIN_S2000 | 同47父／47完整座面 | 2,000 | 15,000 | 16,000；每父338–342次 |

该生成器累计 **15,000次条件更新，其中3,000次为 SEAM 更新、24,000个 SEAM 训练实例**。四个熟悉父额外获得了早期200步的集中曝光。

推理使用的 LONG 布局头来自另一条“四父 SEAM200＋800”训练路径；当前生成器并没有继承 LONG 的那800步。不能把两条分支的训练历史合并计算。

### 3.3 Bench 原完整训练

| 阶段 | 起点 | 新增步数 | 终点 | 每父本阶段曝光 |
|---|---|---:|---|---:|
| COMMON 普通条件 | 官方 Bench EMA＋fresh AdamW | 12,000 | global12000 | 1,500 |
| Native 普通续训 | COMMON12000 | 9,000 | global21000 | 1,124或1,126 |
| SEAM 续训 | 同 COMMON12000 | 9,000 | global21000 | 1,124或1,126 |

两分支共享起点、父／条件／增强流。每个终点的条件训练历史为21,000步；实验有效更新总数为12,000＋9,000＋9,000=30,000，不能把共享历史重复计成42,000。

主要配方：batch8／microbatch1；每更新4个不同父，各原尺度和一次宽度0.9..1.1增强；父均匀循环、父内条件循环。AdamW lr=1e-5、betas=(0.9,0.95)、weight decay=0、clip=1；BF16前向、FP32参数／优化器／积分。SEAM 使用角色受限 OT、HYBRID0.25 和原 FM。

原 SEAM 布局头为833参数逐边头，随训练更新，采用冻结类别权重 BCE。达到预登记最大预算时，TRAIN bulk／all-free 已较平，但 seam-tip 仍未满足平台规则。停止状态为 `BUDGET_EXHAUSTED_NOT_CONVERGED`，不能写成全部收敛。

### 3.4 Bench 最新 CLEAN1500

从 **COMMON12000重新分叉**，不是接着 SEAM21000 训练：

- 58父／195C，新增1500步，终点 global13500。
- 12,000训练实例，每父206或208次；单条件16–208次。父等权不等于条件等曝光。
- C/Y 同步独立 xyz 缩放 U[0.92,1.08]，缩放后 OT，Gaussian 不缩放。
- 新布局头18,049参数，含边间上下文、TRAIN-only 特征归一化和未加权 BCE。
- 生成器仍为原 SEAM／FM，没有新增几何 loss。

这同时改变了条件筛选、增强、头和训练长度。因此可比较整套配方，不能把收益单独归因于“更少训练”“数据更干净”或“新头”。

**同等步数有利于某种预算对照，但不等于两类应该使用相同的最优配方。重复噪声和缩放增强也不增加独立物体数。**

## 4. 过拟合风险有什么实际证据

以下为固定输入、固定监督探针 MSE；不是在线随机 batch loss，也不是自由生成的质量评分。

### 4.1 Bench 原训练：TRAIN 与 DEV 方向相反

| 探针 | TRAIN 起点→终点 | DEV 起点→终点 |
|---|---:|---:|
| COMMON 普通条件 all-free，0→12000 | 0.157445→0.110555 | 0.879781→1.144615 |
| SEAM tip，12000→21000 | 0.573782→0.029562 | 1.886750→2.758679 |

普通条件阶段尚未引入 SEAM 时，DEV 已经恶化。SEAM 阶段 TRAIN 第三点误差大幅下降，DEV 反而继续上升，存在明确的过拟合／迁移退化迹象。

但初始 TRAIN/DEV 差距已经很大，说明两集合本来就不等难；不能把全部差距归为训练造成。固定插值探针还含有目标信息，学好它也不保证自主 rollout 接续成功。

### 4.2 CLEAN1500 缓解了误差，但没有解决终态任务

| 新增步数 | TRAIN all-free | TRAIN tip | DEV all-free | DEV tip |
|---:|---:|---:|---:|---:|
| 0 | 0.11703 | 0.57378 | 1.14951 | 1.88675 |
| 500 | 0.11575 | 0.45269 | 1.10335 | 1.70030 |
| 1000 | 0.11593 | 0.36142 | 1.04520 | 1.67482 |
| 1500，预定终点 | 0.11441 | 0.27986 | 1.05750 | 1.77971 |

新配方的 DEV 探针优于旧长训终点，但1000→1500又出现回升；没有据此事后选择1000步，也不能宣称1500是最佳预算。

## 5. 生成结果究竟差在哪里

### 5.1 Chair 有强熟悉条件收益，但泛化尚未普遍成立

固定 `PLAIN_S2000 + HINGE_OPP015 + ALPHA + HOLE`：

| Chair SEAT | TRAIN 16请求 | DEV 12请求 |
|---|---:|---:|
| seam 经合法共边接入的 bulk 面积均值 | 64.260% | 2.403% |
| bulk 可达面积≥30%的请求数 | 14/16 | 0/12 |

DEV `608/n2` 已达到28.821%的实际可达面积，属于真实但有限进展，不能因未过30%就说完全无效，也不能改阈值宣称全部问题已解决。全28请求该最终流程 FF=12.996%、I=1.697%。

另一个 BACK_FULL 冻结迁移面板16请求：图审用途14 YES、2不确定；bulk≥30%为2/16，最终 FF=18.83%、I=21.18%。靠背的用途正例不能自动等同于低冲突或稳定连接。

所以需要解释的是“Bench 为何没有复制 Chair 的熟悉条件接续收益，以及两类怎样改善泛化”，而不是把 Chair 当成已全面解决泛化的理想对照。

### 5.2 Bench 的 C 侧接上了，bulk 往往仍独立生成

原 SEAM21000 的 BASE_POST：

- 有合法 C/F 边：TRAIN14/16、DEV22/32。
- bulk 可达≥30%：TRAIN0/14、DEV0/26。
- FF：TRAIN33.140%、DEV32.296%；I：TRAIN16.644%、DEV8.452%。
- TRAIN 每份平均删84.19张 free 面，DEV删72.03张；实际存活面数也必须保留，不能只看下降后的比例。

这意味着 **Bench 在已见父上也没有获得 Chair 那样的主体接续**。仅说“训练集学得很好、测试集不泛化”还不够：监督误差拟合与自由生成兑现之间也存在缺口。

将已缓存输出统一执行完整 CPU 级联后，结果如下。均值沿用 Bench 原报告的噪声→条件→父等权，闭合 C 不计作 seam 失败：

| FINAL 流程 | 范围 | FF %↓ | CF %↓ | I %↓ | bulk≥30% |
|---|---|---:|---:|---:|---:|
| 原 SEAM21000 | TRAIN | 29.84 | 4.91 | 16.94 | 1/14 |
| 原 SEAM21000 | DEV | 28.03 | 9.62 | 8.18 | 0/26 |
| CLEAN1500＋旧布局 | DEV | 28.06 | 6.35 | 8.96 | 0/26 |
| CLEAN1500＋新头 | TRAIN | 29.13 | 3.21 | 13.86 | 0/14 |
| CLEAN1500＋新头 | DEV | 29.89 | 6.39 | 11.18 | 0/26 |

新头的来源 owner 召回在 DEV 从68.60%升至94.21%，真 Null 拒绝却从65.63%降至25%。相同新生成器下，新头增加 C/F 共边，同时恶化 FF/I，DEV bulk 仍为0。因此不能把剩余问题简化为“占用头漏开了边”。

### 5.3 用户看到的是宏观用途和表面分配问题

典型坏例包括：

- 蓝色输入本来可以成为座面，生成器却在上方另生成灰色座层，蓝色被包在里面或降为底部挡板。
- C 已含座面和支撑形状，free 仍另造错位的表面，或没有完成合理主体／支撑。
- seam 面在 C 边上存在，但其侧边与 bulk 未建立实际共边；视觉“挨得近”不等于连接。
- D0/GEO 能降低部分冲突，却会伴随细腿、座条削薄或删面，不能补救所有 RAW 中已有的宏观错层。

这些图像支持继续研究生成器对 C 的采用和形状分配，但**不能仅凭图片证明模型记忆了默认高度、记住了训练款式，或者所有失败都是过拟合**。

指标口径：FF/CF分别是非法 free/free、C/free 面对影响的 free 面比例；I 是 C 有限表面查询的冲突覆盖，不是整物体自交率。bulk 可达不包括 seam 自己的面积；≥30%是当前工作阈值，不是论文公认的成品成功定义。RAW、BASE_POST、FINAL 不混用，图审为非盲 AI_PROXY，不冒充人工实验。

## 6. 目前可以判断什么，仍不能判断什么

| 解释 | 当前证据状态 |
|---|---|
| Bench 官方可用类别数据显著少于 Chair | 已核对；但其对当前失败的贡献未隔离 |
| Bench 后训练独立父数远小于 Chair | 不成立：64/58 vs67/47，数量接近，任务不同 |
| 全参数长训存在过拟合／迁移退化风险 | 有 TRAIN 改善、固定 DEV 恶化的直接迹象 |
| 再多训到 TRAIN tip 足够小就会接好 | 未获支持；已降至0.02956，DEV仍恶化、主体仍不接 |
| 只要减少训练步数就能解决 Bench | 未证实；CLEAN1500仍未得到 DEV 主体接续 |
| 只要提高 owner 召回就能解决 | 已有反例：召回升高但 bulk未接、FF/I增加 |
| 只差后处理焊接 | 不支持；多例RAW已有宏观错层，CPU仅有有限修复 |
| Chair 与 Bench 只差类别 | 不成立：任务、阶段曝光、布局头、类别先验和评测划分不同 |
| 平移／缩放增强等于扩大独立数据集 | 不成立；它增加变换覆盖，不新增物体结构 |

类别专用 D0 也不同，本地设置 Chair std=.02、Bench std=.05。这是另一个需要明确的可比性边界，而不是已经证实的失败原因。

当前尚缺：控制其他因素后的独立父规模效应、部位内有效覆盖与近重复程度、较低适配强度的配对结果、共同难度面板上的跨类别比较。尚未运行的平移增强不能列为已有正结果。

## 7. 希望网页版 GPT 重点帮助讨论的问题

请依据以上事实评议，不直接把某个假说写成结论。我们希望优先改进模型视觉质量、C的合理采用及主体接续，避免再叠一串无法归因的局部约束。

1. **Bench 应怎样调整后训练强度？** 普通 COMMON12000 阶段已出现 DEV 恶化，下一轮继续从它分叉是否会继承不利适配？怎样用最小对照判断应保留这个起点，还是从官方 EMA 重新组织较温和的条件训练？
2. **怎样区分覆盖不足与任务跨度过大？** Bench 独立父数与 Chair 接近，却同时学习多部位。优先增加父对象、限定可比的座面任务，还是分阶段引入多部位？请给出能区分这些解释的最小实验，不把多项改动同时混入。
3. **应优先研究哪些抗过拟合手段？** 较小学习率、较短适配、部分参数更新、保留先验的回放／约束等，哪项最有证据适用于已有 flow 生成器？不要仅因网络约1.3亿参数就直接建议缩小网络。
4. **增加真实父对象与平移／尺度增强分别能解决什么？** 本地有504个官方 train Bench UID，但未确认它们都能满足 N128..256 和合法部位条件；请不要把全部504直接当作可用训练池。
5. **怎样定义公平比较与停止条件？** 是否应同时报告更新数、训练实例数、每父及每条件曝光，保留固定噪声终态曲线，并将 TRAIN监督收敛、DEV诊断和开放生成质量分开？
6. 请最终推荐**一个优先实验**，写清它验证的假说、最小对照、固定预算原则、正负结果各意味着什么，以及何时停止。不要预设扩大数据、缩短训练或增强一定有效，也不要要求匹配唯一GT款式。

若引用论文，请核验原文和官方实现，区分实证结果与对本项目的推论。现有历史包含大量未形成稳定升级的边界loss、couple、读取分支、RL和后处理尝试；建议重用某一机制时，应说明它相对现有证据的实质变化。
