# Two-triangle chair control pilot

本轮按用户要求实际试验了“两个三角形拼成完整面片”的条件输入。输入几何已经规整：每片由 4 个唯一顶点和 2 个共面、共边三角形组成，法向一致，没有裂缝、重叠、退化或细长三角形。**这两份噪声下，输入原样保留，自由生成部分出现正向但偏小的宽度响应，尚未形成可靠的座面边界接合。**

## 固定试验

- 模型：保留的 Chair HYBRID START，conditional_total5000，原始权重不变。
- 输入：水平座面，中心 `(0,-0.55,0)`；深度 2.4，宽度分别为 2.4、3.0。两三角形均朝 +Y。两档只改变 X 宽度，输入宽度增加 0.6（25%）。
- 正方形两三角形最小内角 45°，较宽矩形最小内角约 38.66°；共享同一条完整对角边。`inputs/*.obj` 使用真实的 4 顶点 / 2 面索引；NPY 是模型要求的 FP32 三角形坐标。
- 维持原训练坐标尺度，不做输入自动归一化。座面高度及尺度参考现有椅子范围后取整，属于本次明确构造的条件，不是伪装成既有 GT 的重网格。
- 固定 N=160，其中 K=2 已知、158 面自由生成。种子 20261006 与 20261007；同一种子的两档宽度使用逐字节相同的初始自由噪声。
- 共 4 次新采样，每次原始 Euler50、BF16 前向、FP32 参数和积分。实际模型前向 200 次，训练更新、反向传播、优化器更新、几何后处理均为 0；没有额外试跑、重采样或挑选候选。
- 严格 deterministic algorithms、TF32 关闭、SDPA math、`CUBLAS_WORKSPACE_CONFIG=:4096:8`。输入 C 在每次采样全部 51 个状态中逐字节不变，模型 state before/after 一致。

## 两份配对噪声的结果

自由部分宽度只统计 158 个生成面的 X 范围，排除原样插入的 C，避免把“输入本身变宽”误算为生成响应。另列全部自由顶点 X 的 5–95 百分位跨度检查极值影响；该指标不按面积加权，不是专门的座面宽度。

|种子|自由部分 X 宽度，C宽2.4→3.0|自由宽度增幅|自由增量/输入增量|自由 X 5–95 跨度|
|---|---|---:|---:|---|
|20261006|2.41235 → 2.44790|约 1.47%|0.0592|2.34260 → 2.38016|
|20261007|2.61864 → 2.82864|约 8.02%|0.3500|2.54909 → 2.75211|

两份噪声都有同向变化，但响应大小不同，均明显弱于输入的 25% 增宽。这里只能描述本次两个配对样本，不能据此估计总体成功率、证明稳定控制或断言两三角条件完全无效。

边界诊断在输入矩形周长上固定均匀弧长取 256 点，计算到**原始 free 三角面**的欧氏最近距离。不同宽度使用各自完整周长；点数不变，阈值固定为原坐标 0.03。它是本轮新定义的直接几何诊断，不是旧实验的 SeamCov 指标，也不等价于网格焊接率。

|种子|边界距离中位数|边界距离 p95|边界点距离 ≤0.03 比例|
|---|---|---|---|
|20261006|0.31572 → 0.35822|0.35751 → 0.47680|8.20% → 5.86%|
|20261007|0.25021 → 0.33587|0.29295 → 0.37309|6.25% → 4.30%|

两例增宽后该边界接近比例均下降，不能把“蓝色输入仍在输出中”解释为“生成部分已经正确接上输入”。对座面高度 ±0.25 内的自由顶点宽度，seed06 的两档均无顶点，seed07 的两档分别有 11、1 个顶点；不足 3 个时记 NA，因此两份配对的座面带宽响应都为 NA。顶点不足不表示三角面不会穿过该高度带。

本次没有 GT；不报告 Dsym 或宣称完整椅子的误差比上一轮降低。K=2 为接口支持，但条件远少于此前展示的 20% 面片上下文。规整输入与高质量自由生成是两件需要分别核验的事。

- `analysis/metric_definitions.json`：新指标的完整定义；`analysis/*_boundary_distances.npz` 保存边界查询点和逐点真实面距离（实际文件名见分析摘要）。
- `plan.json`、`ledger.jsonl`、`results.json`：冻结条件、预算及执行账本。
- `audit/`：硬件、显存遥测、严格模型加载、调度决策和独立审计。

## 实际资源与执行耗时

调度前 RTX 5080 总显存 16,303 MiB、空闲 12,734 MiB，GPU 利用率 1%；24 CPU 核，可用 RAM 65.88 GB。保留 2,048 MiB 显存余量。一次严格加载耗时 6.721 秒，首个已授权采样实测 3.043 秒，余下三次分别 2.067、1.827、2.219 秒；含加载、检查、保存的执行段约 18.06 秒。

首个样本完成后剩余三项，复用单模型继续执行；单独再开 worker 的严格加载成本已经接近剩余采样总时长，因此没有额外并行加载。实际 1 个 GPU worker、每进程 CPU 2 线程，后续 CPU 分析与图形准备独立并行。该选择依据小预算和实测加载开销，不是显存不足或 GPU 计算饱和。

遥测整卡显存使用峰值为 4,235 MiB，最小空闲 11,745 MiB，整卡利用率最高 30%；包括桌面等用户进程。环境未提供可用的逐进程显存数字，真实进程峰值记 NA。每次采样自身 PyTorch allocated 峰值约 553.21 MiB、reserved 峰值 612 MiB，包含驻留模型和 autocast cache，二者不相加，也不当作含 CUDA context 的完整进程峰值。

## 实际图像检查

已逐张检查输入图、主对照图和侧视图。输入两片连续、平整，共用对角边可见；可视化未移动任何顶点、未平滑、补洞、修复或裁掉异常面。

四个输出中，橙色生成座面均位于蓝色输入面片上方，呈现明显的“双层座面”，没有直接把这块干净输入作为贴合的完成座面。seed20261006 的橙色座面还有明显缺口；seed20261007 的窄输入结果保留一处向下延伸的细长异常面。这与边界距离的诊断方向一致。

两种输入只调整 X 坐标，其他坐标固定，但宽度变化自然也改变面积及边长，不能声称隔离了网络中的某个单独“宽度特征”。确定性设置已核验，本轮未额外重放，不宣称已经实测跨次 GPU 重现性。

独立审计见 `audit/independent_audit.json`：checkpoint 整文件 SHA256、25 个正式源码文件、6 个冻结输入文件、4 次精确预算、所有51态C、同噪声配对及原样OBJ导出均通过。本次生成的原始轨迹与输出保留，固定4样本任务到此停止。
