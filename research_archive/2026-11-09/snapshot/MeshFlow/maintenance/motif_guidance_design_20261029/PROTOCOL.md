## 1. 本轮问题与研究定位

冻结官方Bench完整形状生成器EMA，检验预测终点的条件误差通过输入VJP引导生成状态，是否能改善实际C采用、完整主体和支撑。分开回答：

1. **机制增量**：G3相对同官方先验的G1，是否改善真实完成；G3相对G2是否有全状态直接修正的额外收益？
2. **项目增量**：G3相对现存EXPOSURE，是否改善同请求的RAW与FINAL，而没有不可接受的冲突、碎片或支撑损失？

保留已有Native/SEAM，不将本轮定义为推翻原方法。若通过，再讨论相同算法、相同尺度规则在Chair的迁移；本轮不包含新增Chair采样、SEAM、训练或后端方案。

最近历史对照：R03是当前状态上的软面匹配引导，梯度不经过完整生成器预测；R26是固定F、调整D0内部C副本的反馈。新变量是完整先验终点预测到当前free状态的交叉Jacobian。R26已经说明C预测误差下降不是实际接续的充分条件。[历史登记](../../r2/docs/research_route_registry.json) · [R26报告](../../experiments/r2_c_restore_coupling_v1/REPORT.md)

FrameFlow提供条件训练与冻结先验guidance两种方法及近似likelihood依据。本轮Euclidean MeshFlow、固定无序面对应、nested OT耦合及count CFG均有自身限制，不声称精确条件后验、拓扑保证或已验证的跨类别泛化。[原文§3.2/附录D](https://arxiv.org/html/2401.04082v2) · [官方guidance源码](https://github.com/microsoft/protein-frame-flow/blob/main/motif_scaffolding/twisting.py)

## 6. 引导计算图、能量和限幅

每步在本次更新前状态上计算：

```text
v = v_cfg(X,t)
Xhat1 = X + (1-t)*v
omega2 = ((1-t)^2 / (t^2+(1-t)^2)) + 1e-6
E = sum((Xhat1[:K] - C_model)^2) / (2*omega2)
g = autograd.grad(E, X)                 # parameters frozen
d_full = -h * lambda * (1-t)/t * g
```

仅在`k>=5`即`t>=0.10`执行引导，共45次VJP/引导输出。前5步按无引导速度走。终点估计保持计算图；不得先覆盖C、detach v或把梯度只对预测终点本身求导。

**固定sum能量，不在本轮偷偷改成除以K/面积的均值loss。** 它随条件表示变化的限制必须记录。附带记录不参与控制的`E/(9K)`、端点角点RMS、最大误差和按C/F分开的梯度范数。

本设计补齐文字附件未给具体数值的限幅：固定规范尺度`L=9.208138264587333`，每一步引导修正的任意角点最大欧氏位移不超过`0.005L`（0.5%L）。不是对完整Euler位移限幅，也不是每个角点独立截断。

```text
a = min(1, 0.005*L / max_corner_norm(d_full)) # max=0时a=1
d = a*d_full
G3: Xnext = X + h*v + d
G2: Xnext = X + h*v + mask_S*d
```

**先按全状态修正算同一缩放，再在G2屏蔽F。** 这样相同状态下G2/G3的S修正相同，避免不同限幅分母成为额外变量。该保护与0.5%L属于新的工程选择，不来自云端已验证结果，不扫描第二档。记录每步缩放a、限幅频率、S/F的实际max/RMS修正、相对基线Euler更新范数、累计路径修正量。限幅频繁时不能只用标称λ解释作用强弱。

每次更新后detach状态，不反传整条轨迹。G0/G1也使用相同网络精度和确定性设置。不得复制官方源码里的NaN→0容错：非有限速度/能量/梯度/状态视为明确数值失败并保留现场。

上述系数为待检验近似，未建立MeshFlow nested OT＋count CFG下的精确后验定理。未获得原云端程序，因此不承诺与其符号、方差、归一化或限幅逐位等价。

1. 8请求J总数最多；
2. J打平时，明确碎片/孔洞请求较少；

| RAW有增益，FINAL丢失 | 前端候选；后端问题单列 |

| FINAL跨父任务与质量通过 | 保留新研究候选；Chair迁移另立预算，不能自动追加 |

## 11. 实施检查、资源与恢复

仅一次必要的轻量CPU实现检查：C源/规范角序往返、拼接噪声身份、mask/全局限幅、Euler更新计数、CFG计数/公式、线性解析速度场上VJP与有限差分，以及以下三种不同的错误计算图：detach速度v会消除C→F交叉梯度，但S仍有恒等项梯度；detach完整预测终点会断开计算图，通常报错或返回unused；在保持其余图连接的情况下先覆盖预测C会使能量及梯度为零。分别核验，不把三者都写成全状态零梯度。CPU使用解析小函数，不训练或测试另一个小神经模型，不以解析检查替代真实Bench结果。

真实大模型显存/梯度有效性从**已预算的首条G3校准请求**测量，不另做GPU探针或加样。先处理bcb/n0、λ0.1的正式轨迹，记录完整VJP峰值；如果成功，此输出直接进入本轮，不因观察资源重跑。N520不是N776峰值保证；确认高N首次派发仍保留余量并单worker测量。

设计时只读资源快照：RTX5080，总16303MiB，已用8378MiB、空闲7602MiB、compute2%；Windows显示24逻辑CPU。WDDM逐进程显存/进程名及CIM可用RAM查询未获权限，记UNKNOWN；不杀后台进程，也不据此认定可开两个GPU worker。执行前按AGENTS在实际WSL重新取得资源和活动负载。

初始1个GPU worker；完成代表性VJP测量后，按`floor(max(0,free-headroom)/(1.2*observed_process_peak))`及CPU/RAM/compute决定是否逐个增派，headroom至少2GiB/总量10%的较大值。没有可靠进程峰或算力已饱和时保持单worker。G0/G1、VJP、D0分别估算；D0不得与未完成RAW阶段混跑。CPU评分独立进程最多2起步，每进程1线程，资源允许再调度现有任务，不新增任务。

正式实现应提供独立可恢复总入口，阶段为`prepare → calibrate_raw → lock_lambda → confirm_raw → d0 → geometry → score → review → report`。每输出保存51状态和每步完成账本；只有已提交安全状态才能续跑。非有限、OOM、输入hash不符即停止相关派发并保留现场；零静默重试、零重抽噪声。已提交输出按hash跳过。无法避免的重复计算需要单独披露并获后续授权，本设计无额外重放额度。
